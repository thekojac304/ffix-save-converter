## Framework decision: PySide6 (Qt 6.12)

| | PySide6 | tkinter |
|---|---|---|
| Drag and drop | native | needs tkinterdnd2 (extra native binary) |
| Screen readers | Windows UI Automation built in (the smoke test drives the app through it) | weak on Windows |
| HiDPI | automatic per-monitor scaling | manual; list rows do not scale |
| Look | follows Windows 11 light/dark | dated ttk themes |
| Size | 70 MB folder / 30 MB zip | about 15 MB |
| License | LGPL-3.0: fine with dynamic linking and the folder build (Qt DLLs replaceable) | PSF |

Accessibility, scaling and polish were explicit requirements, so PySide6 won. Size was trimmed from 97 MB: no
translations, no software OpenGL, no network/SVG/QML modules, and no duplicate Qt DLLs.

## Memoria/Moguri findings that shaped the design

- **The container is still written.** Memoria still writes the vanilla container on every save: same encryption,
  layout and schema. Memoria-only state is narrowed onto vanilla fields, and **item ids ≥ 256 silently wrap to a
  wrong item**.
- **The sidecar is linked by name only.** `SavedData_ww_Memoria_{slot}_{file}.dat` is 0-based, and it is rewritten
  without truncation (old tail bytes stay behind).
- **Load order.** Memoria loads the container, then the sidecar overrides it, but only if the play times are within
  1.0 s; otherwise the sidecar is ignored as stale. A missing sidecar means the container is loaded alone. A corrupt
  sidecar makes the slot unloadable.
- **Moguri adds no save data.** It is a visual mod (catalogue category Visual) running on Memoria.
- **No mod list is recorded,** so mods are detected only through values the PS1 cannot hold.
- **Open item resolved.** An older Memoria build stored ability-use counters in story bytes 1101–1291. Those bytes are
  zero in all 118 vanilla saves we have (story positions 1,155 to 11,770), so the converter clears them for PS1.

## Runtime results and verdict (2026-11-06)

**Results:**
- **PS1 → Memoria ✅** Your Disc 2 save loaded with exact stats and continued:
  - the Treno story scene played (story counter 4390);
  - a battle was won;
  - a native save, restart and reload kept the state.
- **Memoria → PS1 ✅** The genuine Memoria save (container + sidecar) loaded in DuckStation:
  - correct disc prompt and exact stats;
  - a PS1 battle, a native save, then reset and reload.
- **Sidecar rules ✅** Timed, stale, corrupt and untimed sidecars all behaved in Memoria exactly as the converter predicts.
- **Moguri-style ✅** The mod-folder setup changes nothing about saves.
- **Vanilla state ✅** Across PS1 → Memoria → PS1, only gameplay results and documented normalizations differ.

**Defects found and fixed (with regression tests on the genuine files):**
1. Saves made after Memoria loaded a vanilla save were refused. Memoria marks Quina/Eiko/Amarant as present and its container drops Marcus from the party. The shared record is now chosen by evidence.
2. A legitimate sidecar whose AP differs from its container was refused. It is now checked against the vanilla ability-id lists.
3. Marcus's PS1 load-screen portrait (cosmetic).

**Verdict:**
- **Promoted to verified (beta):**
  - PS1 → Memoria/Moguri;
  - Memoria/Moguri → PS1 for **unmodified gameplay**, including Moguri-style visual setups;
  - the sidecar precedence and staleness rules.
- **Coverage:** Memoria 2025-07-13 (stable v2025.07.04), Steam build 5378074, DuckStation 0.1-7878, one Disc 2 checkpoint.
- **Still experimental:**
  - saves changed by **gameplay mods** (no real gameplay mod was tested; out-of-range values are refused by default);
  - other story periods under Memoria (the shared-record rule rests on 118 vanilla saves);
  - Moguri with its real textures.

## Known limits

- Memoria → PS1 is **experimental** until the runtime checks above pass.
- A gameplay mod that changes what *in-range* values mean (for example a rebalanced item table) cannot be detected.
- The app is not code-signed (SmartScreen will warn), and has not been tested on a clean machine (Windows Sandbox is
  not installed here).
